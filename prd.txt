# Overview

**Product:** Real Estate "Revenue Recovery" Engine

**Problem:** Real estate agents lose thousands in commissions because they can’t keep up with old leads (dormant databases) and miss high-intent signals on social media. Existing tools are often "gated" (forcing users to sign up), which creates friction.

**Solution:** An agent-centric internal dashboard that automates lead "re-warming," identifies buyers from Facebook posts, and provides instant financial qualification (CPQ) so the agent only calls the "hottest" prospects.



# Core Features

Note: The goal only of this is to build a POC or Mock Website for this. So Just UI with mock data and flow without real api for now.

* **AI Lead Reactivator:**
* **What:** Scans old CSV/CRM exports and sends personalized, low-friction re-engagement prompts.
* **Why:** To monetize "dead" data the agent already paid for.


* **FB Intent Curator:**
* **What:** Aggregates and filters Facebook posts/comments based on intent keywords (e.g., "moving to," "budget for house").
* **Why:** To find "active" buyers in the wild before they hit a portal like Zillow.


* **Smart CPQ (Cost-Price-Quote) Calculator:**
* **What:** A financial engine that computes mortgage estimates, closing costs, and agent commissions.
* **Why:** Enables agents to provide instant, accurate financial answers to qualify leads during the first call.



# User Experience

* **User Personas:** The "Hustler" Agent (wants more deals, low tech-savviness) and the "Team Lead" (wants to optimize their team's existing database).
* **Key User Flows:**
1. **Reactivation:** Upload CSV -> AI analyzes "Last Contact" -> Generates SMS/Email drafts -> Agent hits "Send."
2. **Discovery:** Connect FB Account -> View "High Intent" feed -> One-click save to "Hot Leads."


* **UI/UX Considerations:** Minimalist dashboard. Mobile-first (agents are in their cars). "One-click" actions to reduce friction.

# Technical Architecture

* **System Components:** * Frontend: Next.js (React) for a snappy, responsive SPA.
* Backend: Node.js (Supabase or Firebase for rapid "vibe coding" deployment).


* **Data Models:** * `Lead`: {Name, Contact, Source, Status, Sentiment_Score, Last_Interaction}.
* `Opportunity`: {Post_Content, Platform, Intent_Level, Linked_Lead_ID}.


* **APIs & Integrations:** * **OpenAI API:** For sentiment analysis and drafting re-engagement messages.
* **Facebook Graph API:** For monitoring specific groups/posts (or a scraping middleware).
* **Financial Math Engine:** Custom JS logic for CPQ calculations.



# Development Roadmap

* **Phase 1: The Reactivator (MVP):** Focus on CSV upload, OpenAI-powered message generation, and a basic lead list view.
* **Phase 2: The CPQ Engine:** Add the financial calculator tab. This provides immediate utility even without "data."
* **Phase 3: The FB Intent Curator:** Implement the social listening/scraping component and lead-matching logic.

# Logical Dependency Chain

1. **Auth & Database Schema:** Must have a place to store Leads and User settings first.
2. **The "Calculator" (UI-Only):** Build the CPQ tool first. It’s a "quick win" that creates a usable tool in minutes.
3. **CSV Parser & AI Logic:** Build the ability to import data and have the AI "read" it.
4. **Outgoing Integration:** Connect the "Send" button to a mailto: or Twilio integration.

# Risks and Mitigations

* **Technical Challenges:** FB API restrictions. *Mitigation:* Start with manual "copy-paste" text analysis before building a full API scraper.
* **MVP Scoping:** Don't build a full CRM. Focus *only* on the "Recovery" aspect.
* **AI Hallucinations:** AI might suggest weird financial figures. *Mitigation:* Use hard-coded math formulas for the CPQ; use AI only for text generation.
